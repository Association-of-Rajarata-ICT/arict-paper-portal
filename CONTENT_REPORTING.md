# Content and conduct reports

ARICT repository maintainers accept reports about harmful content, harassment, exposed personal information, inappropriate paper uploads and material that may not be permitted to be shared. Send private reports to [arict@as.rjt.ac.lk](mailto:arict@as.rjt.ac.lk).

## Choose a reporting route

| Concern | Where to report |
| --- | --- |
| Wrong paper details, unreadable file or broken download | [Paper correction issue](https://github.com/Association-of-Rajarata-ICT/arict-paper-portal/issues/new?template=04-paper-correction.yml) for non-sensitive information |
| An accessibility barrier | [Accessibility issue](https://github.com/Association-of-Rajarata-ICT/arict-paper-portal/issues/new?template=03-accessibility.yml) or private email |
| Privacy, copyright, harmful content or misconduct | Private email to arict@as.rjt.ac.lk |
| A security vulnerability or exposed credential | Follow [SECURITY.md](./SECURITY.md); do not open a public issue |
| A missing examination paper | Use Request a paper on [the portal](https://papers.arict.lk/) or contact ARICT |

Include a link to the affected page, file, issue or comment, a brief explanation, and any context needed to locate it. For a paper, add its subject code and examination period if known. Do not repost sensitive or abusive material publicly to report it.

Reports are intended for the maintainers handling the concern. Share only the details needed for review. Maintainers may request clarification, correct or remove material, moderate a conversation, or explain why no change was made. Responses depend on volunteer availability; no fixed deadline is promised.

The [Code of Conduct](./CODE_OF_CONDUCT.md) and [Code of Ethics](./CODE_OF_ETHICS.md) guide this process.

## GitHub's Report to repository admins option

When GitHub's reported-content feature is enabled and you are eligible to use it, the menu on an issue, pull request or comment can offer **Report content** and **Report to repository admins**. If those options are unavailable, use the private email route above. GitHub also provides its own abuse-reporting route for violations of its rules.

## Repository administrator setup

The Community Standards item **Repository admins accept content reports** is controlled by a GitHub setting. Adding this document or an issue template does not enable it.

For a public repository owned by an organization, an administrator can:

1. Open the repository's **Settings** tab.
2. Under **Access**, open **Moderation options → Reported content**.
3. Select a reporting permission option that allows reports, such as **Prior contributors and collaborators**, and save it.
4. Return to the repository's Community Standards page and confirm the setting is reflected there. Review reports in the same Reported content area.

The setting's current state must be checked on GitHub; it is not recorded in this checkout. See [GitHub's reporting-permissions instructions](https://docs.github.com/en/communities/moderating-comments-and-conversations/managing-how-contributors-report-abuse-in-your-organizations-repository).
